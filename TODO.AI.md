## [x] DNS-01 certificate renewal does not reach the live server's TLS listener
Found while debugging the `ERR_CONNECTION_ABORTED` / scheduler-lock intermittent-connection bug session (2026-08-14). Not directly related to that fix; logged separately per project rules rather than fixed inline.
On DNS-01 cert renewal, `src/ssl` builds a new `tls.Config` and assigns it to the manager, but the already-running `http.Server.TLSConfig` pointer was captured at server-start time and is never updated to point at the new config — so a renewed certificate never actually gets served by the live listener until a full process restart.
RESOLVED (audit 2026-08-19). `createTLSConfig` in `src/ssl/ssl.go` now wires a `GetCertificate` callback (`Manager.getCertificate`) into every `*tls.Config`. Go's TLS stack calls `GetCertificate` at handshake time, which resolves the active cert from live manager state under `RLock` — so a `*tls.Config` captured by an already-running `http.Server` serves certs renewed (DNS-01) or reloaded (manual) after startup with no restart. `Certificates` stays populated so `GetCertInfo`/manual reload keep working. Verified with `make lint` + `make test` (green, coverage 81.3%).
